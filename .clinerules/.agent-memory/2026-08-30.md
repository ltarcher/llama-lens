## CLI 整体重设计（llamalens）

### 任务

### 根因
- 旧 `cli/` 是 Go「本机单主机采集器」（~4243 行 / 15 文件）：本地读 /proc + journalctl，`ValidateLocalOnly` 拒绝非本机 llama 端点
- 用户真实 llama-server 在远程 ai.lan（10.0.0.28），由后端经 SSH 采集；开发容器无 llama-server/GPU → 本地采集器永远空视图，指向远程又被拒 → 两条路都死，故"根本不能用"

### 方案
- CLI 重设计为 **LlamaLens 后端的终端客户端**（与 Web 面板同源：轮询 REST 渲染 ANSI TUI，不直接连 llama-server）；删除本地采集器（备份 /tmp/llamalens-cli-old/）
- 新代码 7 文件 1724 行，仅依赖 x/term + x/sys：`cli/main.go`（flag+模式分发）、`cli/internal/client/{model.go,client.go}`、`cli/internal/tui/{format.go,render.go,tui.go}`
- 模式：门户 TUI（j/k/Enter/q）、`--host <id>` 详情 TUI（b/Esc/q/r）、`hosts [--json]`、`--once [--host]`、`--json` NDJSON、`--backend`/env `LLAMALENS_BACKEND`、`--interval`、`--no-color`、`--no-alt`、`--version`

### Bug
1. **Esc 返回键 advertised 未实现**：主机详情页脚写 "b/Esc 返回门户"，代码只处理 b。修复：viewHost 增加 keyEsc(27)。
2. **独立 Esc 与 ESC 序列（方向键）区分**：首版用 `os.Stdin.SetReadDeadline(50ms)` 探测，本环境返回 `file type does not support deadline`（PTY 不可 poll），探测读永久阻塞（最小 Go 实验证实）。修复：`unix.FcntlInt(F_GETFL/F_SETFL)` 临时把 stdin 置 O_NONBLOCK 探测下一字节——有字节=序列（整体吞掉），EAGAIN=独立 Esc；探测后恢复原 flags。
3. 注意：Go 1.25 工具链已移除 `syscall.FcntlInt`，必须用 `golang.org/x/sys/unix.FcntlInt`（x/sys 本就是 x/term 的间接依赖，无新增外部依赖）。

## Terminal 主题"像素感"第三轮（用户反馈"只改了颜色，整体还要像素一点的感觉"）

### 任务
- 用户（BOSS）："这一轮我觉得你只改了颜色，整体还要在优化，像素一点的感觉 terminal 你懂吗"

### 根因
- 前两轮改了结构 + 配色，但**字体仍是抗锯齿平滑渲染** + **CSS 平滑过渡** → 整体还是"web 平滑感"，不是"终端像素块状感"
- 真实终端质感三要素：① 字形无抗锯齿（块状像素）② 重绘即时（无缓动过渡）③ CRT 扫描线/块状条

### 方案（terminal.css 单文件，3+1 处）
- **字体关抗锯齿**（核心杠杆）：body 加 `-webkit-font-smoothing: none` + `-moz-osx-font-smoothing: unset` + `text-rendering: optimizeSpeed` → 字形块状像素化（WebKit/Blink 生效；Firefox 不识别 -webkit- 前缀，退化平滑）
- **即时重绘**：`html[data-theme='terminal'] * { transition: none !important; }` → 禁用所有 CSS 平滑过渡（进度条/仪表/颜色变化即时生效，像终端重绘）；光标闪烁/告警闪烁是 animation 不受影响
- **扫描线增强**：0.012/3px 周期 → 0.028/2px 周期（更明显的像素行纹理）
- **进度条块更离散**：块间隙 1px → 2px（更"像素块"）

### 验证
- `npm run build` 通过，dist 重建（index-A8yj6eIe.css / index-BUiy4F0B.js）
- bundle 校验：`-webkit-font-smoothing:none`、`transition:none!important`、扫描线 `.028` 均入包
- 纯前端，无需重启后端；用户刷新浏览器切 Terminal 主题即可验证

### 重要经验
- "像素感"的核心杠杆是**关字体抗锯齿**（-webkit-font-smoothing:none），比改颜色/加纹理视觉冲击大得多
- 终端质感 = 块状字形（无抗锯齿）+ 即时重绘（transition:none）+ CRT 扫描线 + 块状条，四者叠加才"像"
- -webkit-font-smoothing 仅 WebKit/Blink 生效，Firefox 不识别（跨浏览器像素感有差异，属预期）
- 若用户嫌 none 太锯齿，可退一档用 antialiased（灰度抗锯齿，无次像素）

## 交付前全面检查：性能 + Bug 修复（用户："马上要交了 全面检查下是否有性能问题和bug 全面修复"）

### 范围
- 全量审查 backend（14 个 .py）+ frontend（25 个 .vue/.js/.css）+ 部署文件（Dockerfile/compose/.dockerignore/run.sh）
- 重点：采集器健壮性、WS 推送、事件状态机、代理守护、前端渲染性能

### 修复的 Bug（3 个，均后端）

1. **proxy_supervisor.py FD 泄漏**（中）
   - 现象：`_spawn()` 中 `logf = open(...)` 传给 `Popen(stdout=logf)`，父进程永不关闭
   - 根因：子进程 dup 了 fd，但父进程的 file object 一直持有 → 每次代理重启泄漏 1 个 FD
   - 影响：代理崩溃热循环时 FD 累积 → 最终 `open()` 失败 → 代理无法启动 → 无限重试刷日志
   - 修复：`Popen` 返回后立即 `logf.close()`（子进程已 dup，安全）

2. **proxy_supervisor.py `stop()` 阻塞事件循环**（低-中）
   - 现象：`proc.wait(timeout=5)` 是阻塞调用，在 async 上下文中执行
   - 根因：未用 `run_in_executor` 包装
   - 影响：后端停止时事件循环阻塞最多 5s，延迟整个 shutdown
   - 修复：`await loop.run_in_executor(None, proc.wait, 5)`

3. **llama_api.py `LlamaPoller.start()` 不健壮**（中）
   - 现象：`_poll_fast`/`_poll_slow` 未包 try/except，异常会杀死整个 poller 任务
   - 根因：与 `SshPoller`/`LogPoller` 不一致（后两者都有 try/except 保护）
   - 影响：llama-server 返回一次畸形 `/slots` 数据 → poller 永久停止 → 该主机 llama 采集消失且无重启机制
   - 修复：循环体加 try/except（单周期异常只记 ERROR 不杀任务），与 SshPoller/LogPoller 对齐

4. **events.py `check_alerts` 基线状态误发"恢复正常"**（低）
   - 现象：首次观测（基线）不发告警事件，但恢复循环会对基线状态发"恢复正常"
   - 根因：恢复循环未检查 `last_emit is None`（基线标记）
   - 影响：用户看到没有对应告警的孤立"恢复正常"事件
   - 修复：`last_emit is None` 时静默转 normal，不发恢复事件

### 性能审查结论
- 后端：`RingBuffer.window` O(n) 扫描（3600 点）、`downsample` O(n)、`json.dumps` WS 推送、`evaluate_alerts`/`check_alerts` 每秒 — 当前规模（2 主机）均可忽略
- 前端：`useCountUp` 300ms rAF 动画（有意设计）、`EventFeed` Vue diffing（高效）、`TrendChart` setOption 每 5s（可接受）、`loadHistory` 每 5s（可接受）

- 上一轮把动态标题写在 `BrandBar.vue` 的 `watch` 里，而 BrandBar **只在 PortalView 渲染** → 详情页标题失效
- 更关键：Terminal 主题下用户眼睛盯着的是**假终端窗口标题栏 `.tbar`**（TerminalFrame，显示 `user@llamalens: ~` / watch 命令），那里根本没有速度；速度只写进了浏览器标签页 `document.title`，用户没看那个位置
- 实测后端正常（ai 主机 gen_speed_tps=49.96），数据链路无问题，纯前端展示落点问题

### 方案
- 新建 `frontend/src/speed.js`：全局响应式 `totalSpeed`（门户级聚合）
- `BrandBar.vue`：不再直接写 document.title，改为把聚合速度同步进全局 ref
- `App.vue`：全局 `watch(totalSpeed)` 写 `document.title`（门户/详情任意视图都生效）
- `TerminalFrame.vue`：`.tbar` 标题追加 ` · ⚡ X tok/s`（ANSI 绿 `.tspeed`，仅 speed>0 时显示）——用户真正在看的"标题"
- terminal.css：`--bar-green #b8dcaa→#a8c890 / --bar-amber #f2dca0→#e8d090 / --bar-red #e89098→#e07d85`（在上一轮淡色与原始 ANSI 色之间取中，压暗一档）

### 经验
- **"title" 要先确认用户指哪个**：Terminal 主题下最显眼的 title 是假窗口标题栏 `.tbar`，不是浏览器标签页；两处都放才稳
