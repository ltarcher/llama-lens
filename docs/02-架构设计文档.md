## 1. 总体架构

### 1.1 架构图

```
                    config/hosts.yaml (N 台主机, gitignore)
                              │
┌─────────────────────────────▼──────────────────────────────┐
│  FastAPI 单进程 :8000 (本机部署)                             │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ MonitorRegistry                                       │  │
│  │  ├─ HostMonitor[ai]     ├─ HostMonitor[host2] ...    │  │
│  │  │   ├─ LlamaPoller 1s  │   (每主机独立:              │  │
│  │  │   ├─ SshPoller   2s  │    采集+缓冲+事件)          │  │
│  │  │   ├─ LogPoller (journal 流)                       │  │
│  │  │   ├─ RingBuffer (3600@1s + 1800@2s)               │  │
│  │  │   └─ EventDetector (任务开始/结束/上下线)           │  │
│  └──────────────────────────────────────────────────────┘  │
│  REST: /api/hosts · /api/hosts/{id}/overview|history|events │
│  WS:   /ws/hosts/{id} (1s tick 推送, 可配置)                 │
│  静态:  frontend/dist (Vue3 构建产物)                        │
└─────────────────────────────▲──────────────────────────────┘
                              │ WS 1s / HTTP 降级
              ┌───────────────┴───────────────┐
              │  浏览器 (Vue3 + ECharts)       │
              │  /        主机门户 (卡片墙)     │
              │  /host/:id  单主机详情仪表盘    │
              └───────────────────────────────┘

数据源(每台主机):  llama HTTP API (8080) + SSH 只读批量命令 (22)
```

### 1.2 分层职责

| 层 | 组件 | 职责 |
|---|---|---|
| 配置层 | hosts.yaml + .env | 主机注册：地址/凭证/采集参数/阈值 |
| 采集层 | LlamaPoller / SshPoller / LogPoller | 每主机周期采集 + 日志流，全部只读 |
| 计算层 | SpeedCalculator / DiffEngine | 速度、CPU、磁盘、网络差分计算 |
| 存储层 | RingBuffer | 内存环形缓冲（llama 3600@1s，host 1800@2s） |
| 事件层 | EventDetector | 状态迁移检测 → 事件流 |
| 服务层 | FastAPI | REST + WS + 静态托管 |
| 展示层 | Vue3 SPA | 门户页 + 详情页 |

### 1.3 数据流

```
llama-server :8080 ──HTTP(1s)──▶ LlamaPoller ─┐
                                              ├─▶ SpeedCalculator ─▶ RingBuffer ─▶ REST/WS ─▶ 浏览器
host :22 ──SSH(2s 批量)──▶ SshPoller ─┘         │
                                                └─▶ EventDetector ─▶ EventRing ─▶ /events, WS
```

## 2. 技术选型

| 项 | 选择 | 版本 | 理由 |
|---|---|---|---|
| 后端框架 | FastAPI + uvicorn | 0.115.6 / 0.34.0 | 项目规则技术栈；异步支持；WS 内置；本机已预装 |
| SSH 客户端 | paramiko | 2.7.2 | 本机已预装；持久连接 + keepalive；无需安装 sshpass |
| HTTP 客户端 | httpx | 最新 | 异步请求 llama API（aiohttp 亦已预装，二选一） |
| 前端框架 | Vue 3 + Vite | 3.x / 5.x | 项目规则技术栈 |
| 图表 | ECharts | 5.x | 仪表盘/多序列/堆叠/暗色主题；性能良好 |
| 路由 | Vue Router | 4.x | 两级页面 |
| Python | 3.9 兼容 | 3.9.2 | 本机实际 Python 版本（非 3.11），代码避免 3.10+ 语法 |
| Node | Node 24 | v24.11.1 | 本机实际版本，Vite 兼容 |
| 部署 | 单进程直接运行（run.sh） | — | FastAPI 托管前端 dist；最简单 |

## 3. 多主机设计

### 3.1 核心抽象

```python
class HostMonitor:
    """每台主机一个独立监控单元"""
    def __init__(self, cfg: HostConfig): ...
    def start(self): ...      # 启动 LlamaPoller + SshPoller + 推送任务
    def stop(self): ...
    def snapshot(self) -> dict: ...   # 当前快照（含 alerts）
    def history(self, window_s: int) -> dict: ...
    def events(self, limit: int) -> list: ...

class MonitorRegistry:
    """管理所有 HostMonitor"""
    def load(self, path: str): ...    # 解析 hosts.yaml
    def get(self, host_id: str) -> HostMonitor: ...
    def list(self) -> list: ...       # 门户页数据（各主机摘要）
```

- 每个 HostMonitor 内部运行 3 个独立 async 任务：LlamaPoller、SshPoller、WsPusher
- 任一任务异常被捕获并记录日志，不影响其他任务与其他主机
- 启动时 Registry 加载全部主机；配置变更需重启（本期不做热加载）

## 4. 采集层设计

### 4.1 LlamaPoller（1s）

端点与频率：

| 端点 | 频率 | 用途 |
|---|---|---|
| GET /health | 1s | 在线检测 |
| GET /slots | 1s | Slot 状态 + 速度差分输入 |
| GET /props | 30s | 模型信息、默认参数、模态 |
| GET /v1/models | 30s | 参数量/嵌入维度/词表/文件体积 |

速度差分算法（每 slot）：

```
state: prev_task_id, prev_decoded, prev_prompt_processed, prev_ts, task_start_ts

on_poll(slot):
  now = time(); dt = now - prev_ts
  if slot.is_processing:
    if prev_task_id is None:
        task_start_ts = now                      # 任务开始事件
    if slot.id_task != prev_task_id or slot.n_decoded < prev_decoded:
        # 新任务（或任务边界）：重置基线，本周期速度 = 0
        prev_task_id = slot.id_task
        prev_decoded = slot.n_decoded
        prev_prompt_processed = slot.n_prompt_tokens_processed
        gen_speed = 0; prompt_speed = 0
    else:
        gen_speed    = (slot.n_decoded - prev_decoded) / dt
        prompt_speed = (slot.n_prompt_tokens_processed - prev_prompt_processed) / dt
        prev_decoded = slot.n_decoded
        prev_prompt_processed = slot.n_prompt_tokens_processed
  else:
    if prev_task_id is not None:
        # 任务结束事件：总 token = 最后 n_decoded，耗时 = now - task_start_ts
        emit(task_end, total_tokens, duration, avg_tps)
        prev_task_id = None
    gen_speed = 0; prompt_speed = 0
  prev_ts = now
```

- 任务开始事件：is_processing false→true → 记录 task_start（任务 ID、prompt token 数）
- 模型变更：/props.model_path 变化 → model_change 事件
- 失败处理：请求超时 3s；连续 3 次失败 → online=false + llama_down 事件；恢复 → llama_up 事件；离线期间保留最后数据

### 4.2 SshPoller（2s）

连接管理：
- paramiko SSHClient，AutoAddPolicy（首次连接自动信任指纹并记录日志）
- transport.set_keepalive(15)
- 断线：指数退避重连 1s→2s→4s→...→30s 封顶；断线时 ssh_down 事件，重连成功 ssh_up 事件
- 静态信息（首次连接采集一次）：hostname、内核、OS 版本（/etc/os-release）、CPU 型号、核数

每周期批量命令（1 次 exec，一次网络往返，全部只读）：

```bash
echo ==GPU==
nvidia-smi --query-gpu=index,name,driver_version,memory.total,memory.used,memory.free,utilization.gpu,utilization.memory,temperature.gpu,power.draw,power.limit,fan.speed,clocks.current.graphics,clocks.current.memory,pcie.link.gen.current,pcie.link.width.current,pstate --format=csv,noheader,nounits
echo ==APPS==
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv,noheader,nounits
echo ==STAT==
cat /proc/stat
echo ==MEM==
grep -E '^(MemTotal|MemFree|MemAvailable|Buffers|^Cached|SwapTotal|SwapFree)' /proc/meminfo
echo ==LOAD==
cat /proc/loadavg
echo ==UPTIME==
cat /proc/uptime
echo ==NET==
cat /proc/net/dev
echo ==DISKIO==
grep -E '^(sd|nvme|vd|dm)' /proc/diskstats
echo ==DF==
df -B1 --output=target,size,used,avail,pcent / /share 2>/dev/null
echo ==PROC==
PID=$(pgrep -x llama-server | head -1)
if [ -n "$PID" ]; then
  echo P:$PID
  awk '{print $14, $15, $23}' /proc/$PID/stat    # utime stime vsize
  grep -E '^(VmRSS|VmSize|Threads)' /proc/$PID/status
  ps -o pcpu=,pmem=,etime= -p $PID
  tr '\0' ' ' < /proc/$PID/cmdline; echo
fi
echo ==TOPCPU==
ps -eo pid,comm,pcpu,pmem,rss --sort=-pcpu | head -9
echo ==TOPMEM==
ps -eo pid,comm,pcpu,pmem,rss --sort=-rss | head -9
echo ==PROCS==
ls /proc | grep -c '^[0-9]'
```

差分计算（后端 DiffEngine，基于连续两次采样）：
- 整机 CPU% = 1 - Δidle/Δtotal（cpu 汇总行）
- 每核 CPU% = 1 - Δidle_i/Δtotal_i（cpu0..cpu5 行）
- 进程实时 CPU% = Δ(utime+stime)/Δt/CLK_TCK（相对单核）
- 磁盘读写速率 = Δsectors×512/Δt
- 网络 rx/tx 速率 = Δbytes/Δt
- 首次采样无基线 → 本周期差分指标为 null

### 4.3 EventDetector

状态机（每主机）：

```
llama: online ⇄ offline   （连续 3 次 /health 失败 → offline）
ssh:   connected ⇄ disconnected
task:  idle → running (task_start) → idle (task_end, 带统计)
model: props.model_path 变化 → model_change
```

事件环形：200 条，字段 {ts, level, type, msg}
- task_start/task_end 优先取日志行（launch_slot_ / release）为源，含完整统计（MTP 接受率、上下文占用、耗时）
- boot 事件：日志 "model loaded" 行 → llama_boot（含启动信息）

### 4.4 LogPoller（日志流）

数据源：`journalctl -u {log.unit}`（systemd journal，只读）

采集方式：
- 专用 SSH channel（与 SshPoller 同一 transport，独立 channel）运行 `journalctl -u llama-server -f -o short-iso --no-pager -n 0` 流式跟随
- channel 断开：重连 + 先 `--since "N seconds ago"`（catchup_sec，默认 30s）补拉，防丢行
- follow=false（兜底模式）：周期（2s）`--since "@<last_ts>"` 拉取新行
- 首次连接拉取最近一次启动块（"listening" 前 200 行）解析 boot 信息

日志行格式（short-iso）：

```
2026-08-28T18:11:25+08:00 ai llama-server[55646]: 50.44.267.087 I slot      release: id  0 | task 14847 | stop processing: n_tokens = 201047, truncated = 0
└─ syslog 时间 ──────────┘ └host┘ └unit[pid]┘  └─ llama.cpp 内部时间 ──┘ └L┘ └subsys┘ └function┘ └─ 消息 ─┘
```

解析规则（正则，按序匹配）：

| # | 模式（简化） | 事件 | 提取字段 |
|---|---|---|---|
| 1 | `slot print_timing: id (\d+) \| task (\d+) \| n_decoded = (\d+), tg = ([\d.]+) t/s, tg_3s = ([\d.]+) t/s` | decode_tick | task_id, n_decoded, tg, tg_3s |
| 2 | `slot print_timing: id (\d+) \| task (\d+) \| prompt processing, n_tokens = (\d+), progress = ([\d.]+), t = ([\d.]+) s / ([\d.]+) tokens per second` | prompt_tick | task_id, n_tokens, progress, elapsed_s, speed_tps |
| 3 | `slot print_timing: ... prompt eval time = ([\d.]+) ms / (\d+) tokens \(([\d.]+) ms per token, ([\d.]+) tokens per second\)` | task_summary.prompt | prompt_ms, prompt_tokens, prompt_speed_tps |
| 4 | `slot print_timing: ... eval time = ([\d.]+) ms / (\d+) tokens \(([\d.]+) ms per token, ([\d.]+) tokens per second\)` | task_summary.eval | eval_ms, decoded_tokens, gen_speed_tps |
| 5 | `slot print_timing: ... total time = ([\d.]+) ms / (\d+) tokens` | task_summary.total | total_ms, total_tokens |
| 6 | `slot print_timing: ... graphs reused = (\d+)` | task_summary.graphs | graphs_reused |
| 7 | `slot print_timing: ... draft acceptance = ([\d.]+) \((\d+) accepted / (\d+) generated\), mean len = ([\d.]+)` | task_summary.mtp | acceptance, accepted, generated, mean_len |
| 8 | `slot release: id (\d+) \| task (\d+) \| stop processing: n_tokens = (\d+), truncated = (\d+)` | task_end | ctx_used, truncated |
| 9 | `slot get_availabl: id (\d+) \| task -1 \| selected slot by (LRU\|LCP similarity)(?:, f_sim_best = ([\d.]+).*)?(?:, f_keep = ([\d.]+))?` | slot_select | method, f_sim_best, f_keep |
| 10 | `slot launch_slot_: id (\d+) \| task (\d+) \| processing task, is_child = (\d+)` | task_start | task_id, is_child |
| 11 | 启动行：`loading model '(.+)'` / `n_slots = (\d+), n_ctx_slot = (\d+), kv_unified = '(\w+)'` / `creating MTP draft context` / `upgrading K from (\S+) to (\S+)` / `verbosity = (\d+)` / `listening on (\S+)` / `W` 级行 | boot_info | model, n_slots, n_ctx_slot, kv_unified, mtp_draft, kv_upgrade, verbosity, listening, warnings[] |

状态机（当前状态，逐行更新）：

```
phase: idle → prompt_processing (prompt_tick) → decoding (decode_tick) → idle (task_end)
current: {phase, task_id, n_decoded, tg, tg_3s, prompt_progress, prompt_speed, is_child}
context: {used (最近 task_end 的 n_tokens), total (boot n_ctx_slot), pct, remaining, truncated}
mtp:     {acceptance, accepted, generated, mean_len}   # task_end 时更新
kv:      {f_keep, f_sim_best, selection}               # slot_select 时更新
boot:    {...}                                          # boot_info 时更新
```

速度来源优先级：
1. 日志 tg_3s（3 秒窗口，服务端计算）—— 主
2. /slots n_decoded 差分（1s）—— 日志不可用时兜底
- 前端展示标注数据来源（log / API）

失败处理：
- channel 断开 → 重连 + 补拉；期间 log_available=false，速度回退 /slots 差分
- 行解析失败 → 跳过并计数（parse_error 计数器），不影响其他行
- llama-server 重启（PID 变化）→ 重置状态机，重新解析 boot 信息

### 5.2 环形缓冲

- llama 序列（1s）：gen_speed（tg_3s）、prompt_speed、每 slot ctx_used
- log 序列（按事件）：context.used（n_tokens，task_end 时更新）、mtp.acceptance（task_end 时更新）
- host 序列（2s）：cpu、per_core[]、mem_used、mem_buff_cache、swap_used、每卡 util/mem/temp/power、disk rw、net rx/tx、process cpu
- 实现：collections.deque(maxlen=N) + ts 数组；history API 按窗口切片并降采样（点数 > 600 时取每 k 个）

### 5.3 事件

- deque(maxlen=200)，{ts, level, type, msg}

### 6.2 WebSocket

- 路径：/ws/hosts/{id}
- 服务端 → 客户端：每 push_interval（默认 1s）推送快照（结构同 overview）
- 客户端 → 服务端：{"type": "ping"}（心跳，10s 一次）
- 服务端 → 客户端：{"type": "pong"}
- 心跳超时 30s → 服务端断开；客户端自动重连（1s/2s/4s 退避），断线期间降级为 HTTP 轮询
- 门户页：/ws/portal 每 1s 推送 /api/hosts 数据

## 10. 安全设计

- 凭证：.env（gitignore）+ hosts.yaml 引用环境变量；hosts.yaml 本身也 gitignore（含主机拓扑）；仅提交 hosts.example.yaml 模板
- SSH：密码认证（现状），预留 key 认证（config 字段 key_path）
- 采集命令全部只读，无任何写操作
- 面板监听 0.0.0.0:8000，局域网内使用，无认证（风险已声明，见 NFR-06）
- 前端代码不含凭证；API 不返回密码字段

## 11. 扩展性设计

| 扩展点 | 方式 |
|---|---|
| 新增主机 | hosts.yaml 加条目 |
| 新增指标 | SshPoller 批量命令 +1 行 + 快照字段 + 前端面板 |
| 新增事件类型 | EventDetector 状态机 +1 迁移 |
| --metrics 接入 | 若实例启用 --metrics，LlamaPoller 优先取 /metrics（llama_tokens_generated_total 等），差分法兜底 |
| 同主机多进程 | process.name 支持列表，snapshot.processes[] |
| 历史持久化 | RingBuffer 增加 writer（SQLite），API 不变 |

## 12. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 本机 Python 3.9.2 | 代码 3.9 兼容（不用 match/3.10+ 语法）；依赖全部已预装 |
| /metrics 未启用 | 差分法为主（实测 /slots 字段足够） |
| SSH 断连 | keepalive + 指数退避重连 + 降级显示 |
| llama-server 重启（换模型） | id_task 重置基线；/props 30s 刷新；model_change 事件 |
| 1s 轮询负载 | /slots 为轻量只读 JSON（~2KB）；--threads-http 1 影响可忽略；间隔可配置 |
| IPv6 主机 | paramiko/requests 原生支持 IPv6（已实测连通） |
| GPU1 PCIe x4（异常链路） | 如实展示，用户可在页面判断 |
| 日志格式变化（llama.cpp 版本升级） | 解析规则集中一处（正则表），单点修改；解析失败只跳过该行不影响整体；速度有 /slots 差分兜底 |
| journal 日志量（print_timing 每 3s 一行） | 仅流式跟随 + 首次拉启动块 200 行，不读全量历史；单行解析 O(1) |
