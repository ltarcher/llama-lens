# Agent Memory Rule

你必须为项目建立并维护长期工作记忆。

## 1. Memory 目录

/data/case/jbgs/case1/.clinerules目录中创建.agent-memory目录：


结构：

/data/case/jbgs/case1/.clinerules/.agent-memory/
├── INDEX.md
└── YYYY-MM-DD.md

例如：

/data/case/jbgs/case1/.clinerules/.agent-memory/
├── INDEX.md
├── 2026-08-25.md
└── 2026-08-26.md

如果目录或文件不存在，可以自动创建。

不要做的事情：
不要把.agent-memory到处乱拉，只允许放在/data/case/jbgs/case1/.clinerules目录中

---

## 2. 每次开始任务

开始一个新任务时：

1. 先读取 `.agent-memory/INDEX.md`
2. 判断当前任务是否与过去的工作有关
3. 如果有关，读取对应日期的 Memory
4. 不要无意义地读取全部历史记录

如果用户说：

- “继续上次的”
- “之前我们怎么做的”
- “上次那个问题”
- “以前改过”
- “恢复之前的方案”

必须主动搜索 `.agent-memory/` 中的相关记录。

---

## 3. 每天保存一次工作记忆

完成当天的重要工作后，必须更新：

.agent-memory/YYYY-MM-DD.md

例如：

.agent-memory/2026-08-26.md

当天文件已经存在时，只允许追加或修改相关内容，不得覆盖之前的记录。

---

## 4. 每日 Memory 记录什么

只记录真正有价值的信息：

### 今日完成

记录今天完成了什么。

### 重要发现

记录调查过程中发现的重要事实、隐藏依赖和项目特殊行为。

### 架构决策

记录重要设计决定，以及为什么这么决定。

### Bug

记录：

- 现象
- 根因
- 修复方式

### 未完成

记录没有完成的事情，以及下一步应该做什么。

### 重要经验

记录未来再次开发时可能有用的经验。

---

## 5. 不要保存垃圾信息

不要把完整聊天记录、普通对话、无意义的工具输出、重复日志写入 Memory。

Memory 不是聊天记录。

不要记录：

“用户让我修改代码，我修改了代码。”

应该记录真正有价值的信息，例如：

“发现项目中存在两个同名 Rule，engine.py 实际 import 的不是当前正在修改的文件。”

---

## 6. 必须记录根因

不要只记录：

“修复了一个 Bug。”

应该记录：

“runAsGroup 行号错误。根因是字段不存在时使用了 securityContext 的父级行号作为 fallback。已删除 fallback，并改为只返回目标字段真实行号。”

未来的 Agent 必须能够通过 Memory 理解：

发生了什么、为什么发生、怎么解决。

---

## 7. 记录未完成工作

如果任务没有完成，必须记录：

- 已完成什么
- 没完成什么
- 为什么没有完成
- 下一步应该做什么

不要假装任务已经完成。

---

## 8. INDEX.md

维护：

.agent-memory/INDEX.md

INDEX 只保存重要信息，不保存每天工作的全部细节。

包括：

- 当前项目状态
- 重要架构决策
- 重要 Bug
- 长期经验
- 未完成任务

例如：

# Agent Memory Index

## 当前状态

最后更新：2026-08-26

当前工作：

- Extension Replay
- Check Rule 优化

## 重要架构决策

- Service Worker 负责长期任务
- Rule 自己负责字段行号
- engine 只负责聚合

## 重要 Bug

- runAsGroup 行号曾错误使用父级 securityContext 行号

## 未完成

- Replay 异常流程测试

---

## 9. Memory 与 Rules 必须区分

`.clinerules/`：

记录：

> 以后应该怎么做。

`.agent-memory/`：

记录：

> 过去发生过什么。

不要因为今天遇到一个问题，就立即修改 `.clinerules/`。

---

## 10. 从 Memory 提炼 Rule

如果同一个问题反复出现，或者发现了经过验证的长期工程经验，可以提出：

“这个经验是否应该加入 `.clinerules/`？”

只有用户明确要求，或者当前任务明确要求自动沉淀规则时，才修改 `.clinerules/`。

不要擅自把普通 Memory 变成永久 Rule。

---

## 11. 不保存敏感信息

Memory 禁止保存：

- 密码
- API Key
- Token
- Cookie
- Session
- 私钥
- 数据库密码
- 其他敏感凭证

如果工作过程中遇到这些内容，只记录：

“使用环境变量中的凭证。”

不要记录真实值。

---

## 12. Memory 必须以当前事实为准

历史 Memory 可能已经过时。

如果 Memory 与当前代码、当前测试结果或用户当前要求冲突：

以当前事实为准。

必要时更新旧 Memory。

---

## 13. 任务结束时执行 Memory 检查

完成重要任务后，检查：

1. 今天完成了什么？
2. 有没有重要发现？
3. 有没有架构决策？
4. 有没有 Bug 根因？
5. 有没有未完成事项？
6. 有没有值得未来参考的经验？

如果有，就写入当天 Memory。

如果没有真正有价值的新信息，不要为了“完成任务”硬写一篇日志。

---

## 14. 最终原则

Memory 的目标不是让 Agent 记住所有事情。

目标是让未来的 Agent 不需要重复：

- 已经调查过的问题
- 已经验证过的方案
- 已经踩过的坑
- 已经做出的重要架构决定

工作流程：

任务开始
→ 读取相关 Memory
→ 工作
→ 发现事实和经验
→ 任务结束
→ 更新当天 Memory
→ 必要时更新 INDEX
→ 重复出现的经验再考虑升级为 Rule
